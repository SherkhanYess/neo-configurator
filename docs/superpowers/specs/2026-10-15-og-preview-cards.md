# OG-превью карточки для шарящихся ссылок каталога

Дата: 2026-10-15

## Задача

Менеджеры отправляют клиентам в WhatsApp ссылки на страницы товара
(`/catalog/product/<model>/<cast>/<shape>`). Эти страницы уже интерактивны
(переключение огранок) и уже имеют кнопку в WhatsApp. Но открываемость низкая:
`scripts/prerender.mjs` ставил `og:title`/`og:description`/`og:url`, **но не
`og:image`** — в чате ссылка показывалась без картинки, как голый текст.

Исходно обсуждался интерактивный PDF (отклонён: интерактив в PDF работает
только в Adobe на десктопе) и новая отдельная страница-витрина (не нужна:
страницы товара уже шарящиеся и интерактивные). Остался единственный реальный
пробел — картинка превью.

## Решение

Генерируем на этапе сборки композитную OG-карточку 1200×630 JPEG на каждую
пару модель+огранка (90) + одну дефолтную. Карточка: фото кольца на студийной
панели слева, справа — надпись NEO DIAMOND, название модели, «от N ₸»,
«10 огранок · Сертификат IGI», логотип. Шрифт Jost и палитра paper/ink/
champagne — как на живом сайте.

`og:image` указывает на абсолютный `${SITE}/assets/og/<slug>-<shape>.jpg`
(`SITE` = `SITE_URL`, в проде `https://neodiamond.kz`). JPEG — потому что
WhatsApp ненадёжно показывает webp в превью.

## Файлы (всё аддитивно, существующее не меняет поведения)

- `scripts/og-cards.mjs` — генератор карточек (sharp). Каждая карточка в
  try/catch; возвращает множество успешно созданных ключей.
- `scripts/assets/Jost.ttf` — вложенный шрифт (OFL), чтобы рендер текста не
  зависел от системных шрифтов хоста.
- `scripts/prerender.mjs` — импорт генератора; `page()` получил необязательный
  `image` → `og:image` + размеры + `twitter:card`; в `main()` вызов генерации
  (обёрнут в try/catch) и передача картинки страницам товара и /catalog,
  /catalog/list.
- `package.json` / `package-lock.json` — `sharp` добавлен в devDependencies
  (раньше был только транзитивно), lock синхронизирован.

## Защита «не сломать существующее»

- Генерация и каждая карточка обёрнуты в try/catch. При любом сбое (нет sharp,
  проблема со шрифтом) сборка продолжается, `og:image` просто не добавляется —
  поведение возвращается к прежнему.
- `page()` без `image` выдаёт ровно те же теги, что и раньше.
- Конструктор `con.neodiamond.kz` (`src/configurator/`) не затронут.

## Проверено

- `npm run build` — ✓, 91 карточка, 92 страницы.
- `og:image`/`twitter:card` присутствуют в HTML товара.
- `npm test` — 17 ok, 0 fail.
- Карточки визуально корректны (имя, огранка, цена с сервера).
